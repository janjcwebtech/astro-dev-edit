# Changelog

All notable changes to this project are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses [Semantic Versioning](https://semver.org/): fix-only releases bump the patch (`0.0.x`), releases with feature work bump the minor (`0.x.0`), and the major (`X.0.0`) moves only on an explicitly confirmed bigger release. While the project is in alpha (`0.x.x`), breaking changes may land in minor releases.

## \[Unreleased\]

## \[0.8.0\] - 2026-09-07

### Added

-   **Watch the files change while you edit the page.** *Settings → Editing* gains a **Show changed files in editor** switch (`revealWrites`, off by default) that opens every text file the tool writes in your external editor around the save, so an edit is visible landing in the source and not only in the browser. An existing file is opened at the first line that differs and the write follows after **Delay before writing (ms)** (`revealWriteDelayMs`, 1000 by default, `0`–`10000`, and refused rather than clamped outside that); a new file is written whole and opened afterwards, since there is nothing to watch until it exists. Every text write is covered — page edits, entry saves and creations, collection schemas, a new collection, and the overrides and options in `.astro-dev-edit.json`, with a collection save revealing each of its two stores immediately before its own write — while uploads, imports and deletions are left alone. The launcher is the one behind *Open source*, but the switch is independent of `openInEditor` and cannot confirm that a tab is actually visible, so the timing is best-effort: changes arrive as whole saves, a slow editor wants a longer delay, and a launch failure logs a warning and saves anyway. Saves queue and re-verify at the last moment, so a file you edit yourself during the pause is refused rather than overwritten
-   **Unsplash imports can choose their size.** Every import used to fetch one hard-coded 2400px-wide JPEG, whatever the slot it was going into — bytes committed to the repo that a 480px card thumbnail will never serve. There are now two places to say otherwise: a new `unsplash.importWidth` option (`800`, `1600`, `2400`, `'original'`; `2400` by default, so nothing changes unless you ask), editable in *Settings → Unsplash* without a dev-server restart, and a **size select in the picker's toolbar** next to the shape filter, which starts at that value and applies to the next import only — the right size belongs to the slot, not to the project. The details rail states what the pick will actually download, including "already smaller" for a photo narrower than the choice, since `fit=max` never upscales. A width off that safelist is **refused**, not rounded: it reaches the URL the dev server fetches, so a clamp would quietly import the wrong size. `'original'` strips the width parameter altogether, bounded only by the existing 25 MB import cap. New `atx-unsplash-width` styling hook
-   A **media picker** replaces the inline image browser everywhere images are chosen — the swap panel, the entry drawer's `image()` fields, and the rich body editor's image panel all open the same modal. Project images render as a grid of tiles roughly four times the size of the old 70×50px rows, five columns wide at the default size, sorted **newest first** so a file uploaded a minute ago is the first thing you see rather than buried alphabetically. A details rail shows the selected image's path, size and modified time; the filter and folder-scope controls move in unchanged, and the whole modal is a drop target for uploads. Picking is **staged**: a click selects, the footer's **Use image** commits, and Cancel or Escape writes nothing at all. New `atx-media-*` styling hooks
-   An **Unsplash photo source** in that picker, off unless you opt in with `unsplash: {}`. Search from inside the overlay and the dev server downloads the chosen photo into your project like any other upload — no leaving the browser, and no dependency on a third party once the file has landed, since nothing but the local `src` is written to your source. Every photographer is credited in the grid and the rail with links carrying the `utm_source`/`utm_medium` parameters the API guidelines require, and each import pings Unsplash's download endpoint. Paging is a **Load more** button rather than infinite scroll, and identical searches are served from a 5-minute server-side cache — a demo-tier key allows only 50 requests an hour. New `atx-unsplash-*` styling hooks
-   A **Settings drawer** in the admin bar's overflow menu, where **every integration option is editable in place** — no editing `astro.config.mjs`, and no dev-server restart. Options are grouped into **General**, **Editing**, **Media** and **Unsplash** tabs, each control carrying a line explaining what it does. Changes are stored in `.astro-dev-edit.json` at the project root and take effect on the very next request, including the ones that *narrow* what the editor may touch (`contentRoots`, `editableExtensions`). Options resolve highest-first from `astro.config.mjs`, then that file, then the defaults, so **anything you set in code still wins**: those controls render read-only with a padlock and say where the value came from, rather than accepting input that resolution would discard. `enabled` and `sourceAnnotations` are read before the dev server exists — the second registers a Vite plugin — so both stay config-only and say so. A patch naming any unknown, config-only or locked option is refused **whole**, with per-option messages, so a partly-valid save can never leave the file half-updated. New `atx-settings-*` styling hooks and a `lock` icon
-   The same drawer holds the Unsplash access key, which stays one-way: it is written to `.astro-dev-edit.json` with `0600` permissions so it never has to go near your committed config, and the drawer warns when that file is not covered by your `.gitignore`. The key is never sent back to the browser — a read reports only whether one resolved, from where, and a masked fragment. When a key is set in `astro.config.mjs` or the environment the field is disabled and says so
-   A **collection designer**, opened from its own **Collections** item in the admin bar's overflow menu and shaped after Webflow's collections UI: every collection the project declares, then one collection's field table, then a create form. It is a peer of the Settings drawer rather than a tab inside it — an option is a switch on this tool, while a collection's shape is your own committed source, so reaching the designer does not mean going through a settings screen. It **writes your `src/content.config.ts`** — add a field, retype one, remove one, append a whole collection — and the patch is surgical: comments, key order and quoting outside the edited span come out byte-for-byte as they went in. Adding a field through the panel and removing it again leaves the file exactly as it was
-   Each field row spans **two stores, and says so**. The *Schema* half (type, required, default) writes committed source and changes what `astro build` accepts; the *Editor* half (widget, label, hidden) writes `.astro-dev-edit.json` and only the entry drawer reads it. A save reports each half separately, so "schema written, editor settings unchanged" is a thing the panel can actually tell you
-   An **Items view** per collection, listing its entry files newest-first with draft flags — which is how you reach a draft, or an entry whose route doesn't exist yet, without a rendered page linking to it. Clicking one opens the existing entry drawer; **New item** and delete reuse the endpoints they always did
-   Schema writes are **etag-guarded and all-or-nothing**: a batch is applied to one in-memory copy and written once, so a refusal anywhere leaves the config untouched, and a panel that read the file before someone else changed it is told to reopen rather than merged blindly
-   The designer **refuses rather than guesses**. A schema built by a helper, holding a spread, or otherwise not a provable `z.object({…})` is reported as unreadable and offers *Open source* instead of controls; an `image()` field on a plain object schema says to convert the schema to `({ image }) => z.object({ … })` first, because only that form receives Astro's helper
-   A schema save makes Astro resync its content layer, which reloads the page. The designer now **reopens itself in the collection you were editing**, using the same `sessionStorage` trick that already carries edit mode across the reload every text save causes
-   `schemaEditor` integration option (`true` by default). `false` keeps the whole designer read-only for the schema half — collections and fields still list, and the editor-only overrides still save, since those never touch committed source
-   A field whose widget/label/hidden `astro.config.mjs` owns now renders read-only with a padlock in the designer, the same honesty the option controls already have — storing a value the config outranks would do nothing
-   New endpoints: `POST /collections`, `POST /collection/schema/apply`, `POST /collection/create`, `POST /collection/entries`, `POST /collection/open`, plus a `collections` icon and `atx-collections-*` styling hooks
-   `unsplash` integration option (`false` by default), with `accessKey`, `appName` and `perPage`
-   The image swap panel now shows the **image you are editing**, with its filename and size — previously you edited alt text with no view of what you were describing. Below it, a strip of the six most recently added images makes the common "swap in the thing I just uploaded" case a single click, with **Browse all** opening the full picker
-   `GET /health` reports `unsplash`, so the overlay renders the source tabs only when the feature is both enabled and holding a usable key. A project that never opts in gets a single-source picker rather than a tab that errors when clicked
-   New endpoints: `POST /unsplash/search`, `POST /unsplash/import`, `GET /settings`, `POST /settings`
-   New endpoint `POST /page-source`, answering "which file is the page at this URL written in" from Astro's route manifest, which the integration now reads through the `astro:routes:resolved` hook — dev-only and read-only like everything else here, and re-read on every route change so a page added mid-session resolves without a restart
-   `GET /health` also reports `openInEditor` and `entryEditor`, so the overlay hides the affordances an option has switched off — the entry button and the *Open page source* menu item — the moment you save, without a reload

### Changed

-   **The hover highlight is one mark, and it stands clear of what it marks.** The box around the hovered element sits 2px outside its bounds instead of flush against them, so a heading's ink and the verdict's colour stop touching, and the element tree's locked selection is drawn by the same geometry so the two never disagree by a pixel. The verdict colour now belongs to that box alone: the pill dropped the coloured left edge that restated it, and with nothing to break its symmetry its corners are rounded concentric with the `open` and `copy` buttons inside it — the buttons' radius plus the padding around them — so the pill reads as wrapping them rather than being clipped by them.
-   **The hover highlight is a box around the element, not a box on it.** The outline sits two pixels clear on every side, so it reads as a mark *about* the element rather than as part of it — worst before on a heading, whose ink runs to the edge of its box. The element tree's locked selection places itself through the same helper, so the two figures can no longer disagree by a pixel. The pill above it loses the coloured left edge that repeated the outline's verdict: the box carries the colour, the pill carries the words.
-   **An outline button is a body inside an edge, not a line around nothing.** *Cancel*, *Close* and every other outlined control is drawn the way shadcn's dark outline button is: a faint fill (new `--atx-control-bg`) inside a 1px `--atx-input` edge. Both halves matter and the fill matters more — with a transparent body it read as bare text beside the filled confirm it is paired with, even though the two boxes measure the same 32px. The edge moves off `--atx-border`, which is the separator token and is allowed to sit under the 3:1 non-text floor; a control the user has to see to operate is not.
-   **The collection designer is on the same measure as every other card in the overlay.** A field card carries 16px of padding rather than 10, sits 12px from the next one, and closes with its zod expression under a hairline, so a schema of nine fields reads as nine things instead of one dense block; a store's caption, its control rows and its labels are on the same 12px/14px scale the entry drawer's fields use. The entry rows in the Items view carry the same box as a row anywhere else.
-   **A locked setting keeps its label.** A field whose value `astro.config.mjs` owns dims the control and explains itself with a padlock note — the label above it stays full strength, like every other label in the drawer. Muted ink there made a decided setting read as a lesser one.
-   **The admin bar is one height and has no corners.** Its launcher mark, its chips and its icon buttons all measure 28px — the small rung of the button ladder — so the row reads as one strip rather than three sizes, and an icon button is actually square. The bar spans its edge, so it draws no radius of its own.
-   **The element tree marks branches, not leaves.** A row with children carries a chevron; a row without one carries nothing, with the tags still column-aligned by the chevron's own width. The dot that used to fill a leaf's slot read as a list bullet in front of every leaf in the tree.
-   The **markup and expression editors** put 10px between a box and the label naming it, matching the gap a form field gives its own label.
-   **Every control in the overlay is drawn as a control, and each surface has one loudest thing.** A footer action always carries an edge: **Close** and **Cancel** are outlined wherever they appear, so a band of decisions no longer holds a bare word floating on its ground. The quiet button variant keeps full-strength ink and is reserved for a control that sits *inside* something that already frames it — a card header's corner action, a markdown-toolbar key, a menu item — and the *Browse all*, *Browse…*, *Upload file…*, *Retry* and asset-scope buttons, each of which had grown its own private copy of the outline button, now share the real one and cannot drift from it again. The muted ink is for text being read: a key/value pair's value, a control's row, a form control's own label and the markdown toolbar's keys are back at full strength, since a control painted in the caption colour looks disabled before it looks quiet.
-   **The collection designer's Save is where the decision is.** *Save changes* — and *Create collection* in the new-collection form — sits in the drawer's footer band beside Close, so it stays on screen with a field list longer than the drawer. The band is a slot the pane fills with whatever completes the view it is showing, and the list view, which completes nothing, leaves it empty. The way back out of a collection is a button rather than a coloured link, in neutral ink: the brand purple means *this is on your page and editable*, and the tool's own navigation is not that.
-   **No glyph in the overlay is the platform's.** The markdown toolbar's quote, link and image keys and the media grid's selection tick and broken-thumbnail fallback were unicode dingbats and emoji, which arrive in colour and at a different weight and baseline in every platform font; they are [Lucide](https://lucide.dev) strokes in `currentColor` like every other mark the overlay draws. `quote` and `link` are new to the icon set
-   **A field's two stores sit side by side, and the collections list reads as a list.** In the collection designer, a field's *Schema* half and *Editor* half are two columns of one card rather than one stacked above the other — they describe the same field, and the card's whole job is letting you read one against the other. They stack again only in a drawer too narrow to keep a control beside its label. The collections list itself is a divided list running edge to edge in its card: rows sit flush, a rule separates them, and the hover fill covers the whole row instead of an inset tile.
-   **Every dropdown draws its own chevron.** The browser's arrow sat hard against the control's right edge at whatever weight the platform chose, which is the one place the overlay's chrome was not its own; it is now a 16px chevron inset 10px, matching the icons beside it, and it brightens with the control on hover. In the element tree the **tag is full-strength ink** against the muted preview and a fainter, tabular-figure location, so a long tree scans by shape rather than reading as one grey run. Grayscale antialiasing, kerning and `optimizeLegibility` now also reach the form controls, whose own UA font reset had been stopping them at the control boundary
-   **The overlay's panels are built out of cards, not runs of controls.** Every drawer now stacks bounded surfaces — a card names its concern in the header, carries its fields in a body, and puts the action that completes it in a footer band below a rule. The entry drawer separates **Frontmatter** from **Body** and says where its fields came from (the collection's schema, or inference from the file's own values); the create drawer adds a **File** card, because the slug is the filename and the URL rather than a frontmatter key. The Settings drawer's tabs each become a card headed by the group's name, with the Unsplash access key a card of its own. The Collections list is a card of rows — icon, name, then path and counts — with **New** as a corner action on the header rather than a button trailing the last row. A drawer's title bar is itself a card header: the name at 16px with the file path on a second line, and the corner action pinned across both rows. The scrolling area is a canvas one step darker than the cards on it, so a card's edge is a real boundary
-   **Save and Cancel read as one decision, and Delete does not.** A destructive action goes to the far end of the footer band, away from the pair the user is actually choosing between; **Cancel** is an outline button beside the filled confirm. The entry drawer's Delete carries a `trash` icon and its New a `plus`, both new
-   **The overlay's chrome is neutral and the brand purple has exactly one meaning: *this element on your page is editable*.** The purple was previously the fill on every primary button, active tab, toggle and admin-bar chip *and* on the hover outline and pill, so it marked nothing in particular. It is now `--atx-brand`, reserved for the overlay pointing at your content — the editable outline, the save veil, an element-tree row aimed at a live node, and the launcher glyph. Everything the tool says about itself is neutral, and its emphatic fill (`--atx-primary`) is a near-white with dark ink, on shadcn/ui's dark scale. **`--atx-primary-text` is renamed `--atx-brand-text`** with no alias, and `--atx-destructive-text` and `--atx-destructive-border` are **removed**: a light `--atx-destructive` reads as ink, as a border and as a fill, so the error line, the Delete outline and the failure toast are one colour instead of three. `--atx-brand` and `--atx-input-bg` are new. See [docs/STYLING.md](docs/STYLING.md)
-   **The overlay has a focus indicator.** Every button, field and tab draws a 3px ring on `:focus-visible` — the keyboard only, not on mouse clicks. Entry-drawer fields also set `aria-invalid` from the same call that shows their error line, so the red border and what a screen reader is told are one fact; the border was previously the only signal a field had failed validation
-   **Controls are built on shadcn's anatomy**, measured against the live components. A form control has **no border at rest** — its edge is where its translucent fill stops, and the 1px border is held in reserve for focus and for an invalid value. Controls and buttons are 32px on a 14px/500 scale; the radius ladder is one knob off a 10px base — 6px a swatch or checkbox, 8px a small button, menu item or tab, 10px a form control **and** a button, 14px a panel, drawer or card, and `full` reserved for badges. A button and the field beside it share a rung, which is what makes a mixed row read as one object. Icons inside a control are 16px. Hover moves a surface to the new `--atx-accent` and never tints it, and a pressed button moves 1px. The checkbox is drawn rather than tinted, so it is a 4px filled square that goes near-white with a dark tick when checked. Fields sit 20px apart. **This is a deliberate deviation from WCAG 1.4.11** for the resting control boundary, which no translucent fill can meet: `--atx-ring` carries the 3:1 instead, which is why the focus ring is 3px and always painted on keyboard focus, and text inside a field still clears AA
-   **The icon set is drawn from [Lucide](https://lucide.dev)** (ISC), the library shadcn/ui itself ships with, so the overlay's glyphs sit on the same 24-box, 2px-stroke construction as the controls around them. Four deviate on purpose and say so at their definition: the three panel icons keep a **filled band** rather than Lucide's single divider line, because at 14px in the admin bar the fill is the only thing that says which edge the bar is docked to; the spinner keeps its two-arc ring, whose dim half is what makes the rotation readable; the launcher's pointer is filled, being an identity rather than a glyph in a row; and the status dot stays hand-drawn, since Lucide's `circle-small` is a ring. *Open page source* now carries the `code-xml` glyph — the slash is what reads as source rather than as a pair of brackets
-   A locked field — one whose value `astro.config.mjs` owns — dims only its control. The label and the help text that explain *why* it is locked stay at full strength
-   **The overlay renders inside a shadow root**, on a single `<astro-dev-edit>` element, which makes it immune to the host page's CSS: selectors do not cross a shadow boundary in either direction, so a `*{ color: red !important }` rule on your site leaves the toolbar untouched, and nothing the overlay draws can leak into your layout. Inheritance is the one thing that does cross, and `:host { all: initial }` closes it — a global `p { color: … }` no longer tints text inside the drawers. **Theming moves with it, and `atx-*` classes are no longer a theming API**: CSS written against them cannot match across the boundary. Override `--atx-*` custom properties on `astro-dev-edit` instead, or reach for one of six `::part()` names — `bar`, `panel`, `drawer`, `backdrop`, `pill`, `toast`. See [docs/STYLING.md](docs/STYLING.md). The entry drawer's markdown writing surface is the deliberate exception: it stays in the light DOM and is slotted into the drawer, because Safari's selection and `execCommand` APIs do not operate on a `contenteditable` inside a shadow root, which would leave the formatting toolbar inert
-   **The overlay's colours are a design system, on the [shadcn/ui](https://ui.shadcn.com) naming scheme.** Every surface, ink, border and status colour is now a semantic token — `background`, `card`, `elevated`, `border`, `input`, `ring`, `foreground`, `mutedFg`, `primary`, `destructive`, `chart1`–`chart5` and the rest — defined once in `src/client/ui.ts` and authored in OKLCH, replacing roughly fifty one-off hex values spread across the client. The greys are **achromatic**: the old panel, menu and row surfaces all carried a faint violet cast (chroma ~0.03), which is gone, so the overlay's own chrome is neutral against any site and only the brand and status colours carry a hue. The brand purple is unchanged. `RADIUS` is the matching corner scale on shadcn's single-knob `sm`/`md`/`lg`/`xl` steps plus `full`, collapsing nine ad-hoc radii to five. Buttons take shadcn's variant names — `default`, `secondary`, `outline`, `ghost`, `destructive`. The rich-text editor keeps its light page, as its own `PAPER` token group rather than the dark tokens inverted. `tests/contrast.test.ts` holds every token to WCAG AA and 1.4.11 against all three surfaces — shadcn's own dark defaults do not all clear those floors, so a few tokens sit lighter than upstream
-   The copied element context no longer carries an **Editability** line. That verdict describes what this overlay can edit in place, not what the element is, and an assistant handed the context read it as a constraint on what it was allowed to change. Every other line is unchanged
-   **The project is now `astro-dev-edit`.** `astro-text-edit` named only the first thing the tool did; it now edits images, entry frontmatter, collection schemas and its own settings, and the new name says what actually bounds it — the Astro **dev server**. Every name-shaped surface moves with it, and all of them are **breaking**: the package and repository (`github:janjcwebtech/astro-dev-edit`), the default export `textEdit()` → `devEdit()`, the public option type `TextEditOptions` → `DevEditOptions`, the settings file `.astro-text-edit.json` → `.astro-dev-edit.json`, the endpoint prefix `/__text-edit` → `/__dev-edit`, and the opt-in page-source meta tag `astro-text-edit:page-source` → `astro-dev-edit:page-source`. There is no migration shim: rename an existing settings file by hand, or it is ignored and the defaults apply. The `atx-*` styling hooks are **unchanged**, so custom CSS keeps working; overlay preferences held in browser storage (admin-bar position, element-tree state) reset once, because their keys moved too
-   The overflow menu lists *Open page source* above *Collections*, putting the one-click action first and the drawer-opening items together above the dev-server status
-   **The README is an index with a screenshot per feature, not the whole manual.** It had grown past 7 000 words — a 35-minute read before `npm install` — because each release's changelog entry was being rewritten into it and nothing was ever removed. It is ~1 800 words: the pitch, install, **one list of what the tool does with a screenshot under each item**, the options table, undo-is-git and the limits. The twelve screenshots live in `docs/images/`, taken from the example playground. The detail moves to four new docs — [`docs/EDITING.md`](docs/EDITING.md), [`docs/ENTRY-EDITOR.md`](docs/ENTRY-EDITOR.md), [`docs/MEDIA.md`](docs/MEDIA.md) and [`docs/STYLING.md`](docs/STYLING.md) — linked from a contents table at the foot. No user-facing information was dropped: the two upload-directory constraints moved into the media and entry-editor docs, the Unsplash session-lifetime and CSP caveats into the media doc, and the designer's name-validation rule into the entry-editor doc
-   The styling-hook list is **rebuilt from source and grouped by surface** instead of being one 960-word paragraph. It had drifted both ways: four hooks it documented no longer existed, and around forty real ones were missing. Its `-suffix` shorthand was also inventing names — `atx-rte-image-panel` + `-slot` reads as `atx-rte-image-panel-slot`, when the real class is `atx-rte-image-slot` — so every name is now spelled out in full
-   Three README links to the entry-editor section pointed at `#entry-editor-cms-panel-for-content-collections`; the heading's em dash makes the real anchor `#entry-editor--cms-panel-for-content-collections`, so all three silently went nowhere
-   The media picker's arrival **removed** three styling hooks the old row-based asset browser carried — `atx-asset-row`, `atx-asset-controls` and `atx-asset-count` — along with the generic `atx-drop`, now `atx-media-drop` / `atx-media-dropzone`. `atx-asset-filter` and `atx-asset-scope` moved across unchanged. Custom CSS targeting the removed four has nothing to match; the README's hook list is corrected to say so
-   `GET /assets` now returns `{ path, size, mtime }` per image instead of a bare path string, which is what makes the picker's newest-first sort and its caption line possible
-   The overlay now layers *below* Astro's dev toolbar instead of above it. Every surface — admin bar, hover pill, element tree, panels, drawers, modals — derives from one base z-index, which moved from `2147483000` to `1999999000` so the whole stack (base + 10) clears the toolbar's `2000000010`. The toolbar is the source of the `data-astro-source-*` annotations this integration reads, so covering its own UI was the wrong way round
-   The admin bar's **Elements** button now carries the same icon as the element tree's edge tab (`#atx-tree-tab`) — the left-panel glyph — instead of its own tree-outline one. Both controls open the same panel from opposite ends, so they now read as one control. The unused `tree` icon was dropped from the icon set
-   **Options are resolved per request rather than captured at startup.** Every option previously became a fixed value when `astro:server:setup` ran, which is why changing one meant a restart; the middleware now reads them through a resolver on each call, the shape `unsplash.accessKey` resolution already used. Two visible consequences: a feature gate no longer decides whether its routes are *registered*, so a disabled feature answers with an explicit refusal instead of a 404; and `GET /settings` returns the full option set as self-describing records, so the drawer renders whatever the server declares and adding an option needs no client change
-   Turning a feature off no longer discards how it was configured. `.astro-dev-edit.json` keeps a feature's on/off flag beside its detail, so switching the entry editor or the Unsplash source off and on again brings back its per-collection widget overrides and its app name rather than coming up empty
-   A boolean field now shows its state in words next to the checkbox — `On`/`Off` once the key is set, `not set` while it is absent — instead of a bare, unlabelled box
-   **Overlay ink was audited against WCAG AA contrast, and the failures fixed.** The audit found the secondary ink (`COLOR.muted`) sitting at 4.5:1 at 11px — technically passing, practically hard to read — and a handful of genuine failures underneath it: the source peek's line numbers at 2.8:1, the "⋯ N more lines" marker and the media grid's empty-tile glyph at ~3:1, and the overflow menu's status footer at 2.2:1. `muted` is lifted to a value that clears 5:1 on the lightest surface the overlay paints, and a second step, `COLOR.faint`, is introduced for the genuinely tertiary inks (line numbers, empty states, the menu footer) so "quiet" no longer means "unreadable"
-   The solid `accent` was being used as a **foreground** in three places — the hover pill's *editable* verdict and the element tree's active row and location — where it measures 2.7:1. `COLOR.accentText`, which exists for exactly this reason, is used instead; `COLOR.err` had the same problem as error *text* and gains a matching `errText`. The success toast's green was darkened so white text on it clears AA rather than sitting at 4.3:1
-   Input, textarea, select and outline-button **borders** are no longer invisible. `#444` on a `#111` field measures 1.9:1, well under the 3:1 WCAG requires for a control's boundary; a single `COLOR.control` token replaces the four different greys previously hardcoded across the pickers and the button styles
-   The admin bar's background went from 78% to 94% opaque. Over a *light* page the old value let the page through to an effective `#494853`, which pushed the bar's own hint and menu inks to ~3:1 — the blur still reads as glass at 94%, and over a dark page the two are indistinguishable. Its resting opacity also moved from 0.5 to 0.72: at 0.5 the bar's own labels composited down to 2.8:1 against a white page, making the resting bar the least legible thing the overlay drew
-   The overlay's primary accent moved from `#7c5cff` to a deeper `#6144d7` — the edit-mode toggle and every primary button, the hover outline and its pill, the editable-text veil, the element tree's active row, the admin bar's mark and its accent edge. The translucent tints derived from it (the hover fill, the veil, the tree row, the rich-text blockquote) were re-derived from the new value; the lighter purples used as *text* on the dark panels are unchanged, as they read as the same family and are tuned for contrast rather than to the brand hex. The playground's own `--accent` still carries the old value
-   **The hover pill's copy button says what it copies, and copies less of it.** It reads **`copy context`** rather than `copy`, and the block it produces is a fraction of the size: five source lines either side of the element instead of thirty, twelve CSS rules instead of forty — the ones naming this element kept ahead of the site-wide defaults it merely matches — and no rendered box-and-type line, which is measured geometry an assistant cannot act on in source. What the payload is for is naming one element and where it is written, and at the old caps a one-line `<a>` arrived under ninety lines of its neighbours. Everything that identifies the element is still there, every cap still announces itself in the payload, and the whole file is one source peek away

### Fixed

-   **Picking a `src/assets` image for a body or a plain `<img>` no longer writes a path that 404s once built.** The asset directories deliberately span two worlds — `src/assets` has to be listed so `image()` fields have somewhere to browse — but only your public directory is copied into `dist/`, so `/src/assets/hero.svg` is a URL the dev server serves and the built site does not have. The listing now says which of the two each file is in, decided from Astro's configured `publicDir` rather than a hardcoded `public/`, and the picker acts on it: in a body image panel or the swap panel's *Browse all*, a `src/assets` tile is **visible, dimmed and captioned with the reason** rather than quietly dropped, and it cannot be selected; in an `image()` field the same tile is pickable and a `public/` one is refused the same way. Refusing at pick time is the point — the same value checked at save time would be a refusal after the work looked done. `AssetInfo` gains `servable` and the `/assets` response gains `publicDir`, and both the served path and the upload-dir startup warning are measured against the configured public directory, so a project on `publicDir: 'static'` is no longer told its images live at a URL the site does not have. New `atx-media-reason` styling hook

-   **A layout still emitting the pre-0.7 `astro-text-edit:page-source` meta gets told so.** The rename has no shim, deliberately — but the failure it causes is silent from every angle: the *Edit entry* button hides itself, the create, delete and body-editing flows behind it are simply absent, and `/health` still reports the entry editor as on, because the server never sees a tag only the client reads. One console line now names the old spelling and the new one. The old name is still not honoured

-   **A refusal now says when it is talking about a different element than the one you clicked.** Astro annotates only what is written in the file, so a `<Button>` component's rendered `<a>`, and everything slotted in from an MDX body, carry no source location and the click is answered about the nearest ancestor that does. Refusing is correct — none of it is editable in place — but the *reason* belonged to that ancestor, so a one-word button could be turned down for "containing nested markup" it plainly does not contain. The notice opens with a line naming the tag you clicked and saying a component or slot rendered it; an element written in the page itself is unchanged. New `atx-notice-lead` styling hook

-   **An attribute spelling out an entity could be written once and then never edited again.** Put the five literal characters `&amp;` in an image's alt text and the first save was correct; every save after it was refused with *the source alt no longer matches the page (it may have been edited elsewhere)*, and reloading — the one thing the message asks for — produced the same refusal, because nothing had changed. Astro's compiler decodes an attribute value while parsing the template and emits it without re-escaping, so what the page shows is two decodes deep while the verify step read one. Attribute verification now compares against the source at **every** decoding depth, which is what makes it independent of how many passes the renderer between the file and the page performs. It stays exact about everything else: whitespace is still significant, and a value that is not the source at any depth is still refused

-   **Swapping in an image whose filename holds a space wrote a raw space into `src`.** Browsers forgive it on the way to fetching the file, so the page looked right and the attribute was quietly not a valid URI — and it did not match the way the same project writes the same path by hand. The swap panel now writes the URL form, `src="/brand/Logo%20Miramar%20horizontal.png"`, while the panel's preview, its labels and the picker's tooltips keep the plain filename, which is the half a person reads. An attribute the panel did not choose is never re-encoded, so a hand-written `%20` survives an alt-only save intact

-   **The uncommitted-secret warning could not appear while the Unsplash photo source was off.** The Settings drawer paints that warning — *`.astro-dev-edit.json` is not in your `.gitignore`* — from the same pass that paints the access-key card, and that pass returns early when the photo source is off. So the one case the warning exists for was the one case it stayed hidden: the file is created the moment *any* tab saves an option, and a project that has never touched Unsplash still ends up with it untracked on disk. It is now painted from the settings file's own state, on every tab, whatever the photo source is set to, and says what the file holds rather than only what it might hold

-   **Astro's own dev toolbar swallowed clicks on the overlay's modal surfaces.** The toolbar pins itself at `z-index: 2000000010` and hangs an invisible hover hitbox above its bar, and every overlay surface sat about a million below it — so any control that happened to land in the bottom-centre band was unreachable by mouse while looking perfectly ordinary. The entry drawer's **Delete…** is where it bit at ordinary window widths. Modal surfaces — backdrop, panel, drawer, toast — now stack above the toolbar, which is what a surface that has drawn a backdrop over the page is entitled to; the ambient chrome (hover mark, element tree, admin bar) stays below it, so the toolbar is still there to click when nothing is open

-   **Creating an entry from another collection's Items drawer navigated to a 404.** The destination after a create was derived from the browser's current path, on the assumption that the new entry is a sibling of the page you are looking at — true from a detail page in that collection, false from Collections → Items, which opens an entry in a collection you have not navigated to. The file was written correctly, and then the page 404'd, so a create that fully succeeded looked like it had failed. A destination that cannot be justified is no longer guessed at: the drawer stays put and the toast names the file that was written. Creating from a detail page in the entry's own collection still follows the sibling route

-   **The entry drawer's *New* button threw away an unsaved draft without asking.** Cancel, Escape and the backdrop all confirm before discarding edits, but *New* tore the drawer down unconditionally and opened the create form over it. Nothing had been written, and undo is git, so the draft was simply gone. *New* now asks the same question every other way out of a dirty drawer asks

-   **An image whose filename held a space vanished from a body on the next save.** A markdown destination ends at the first space or paren, so `![Logo](/brand/Logo Miramar.png)` was never an image — reopening the entry read it as literal text, and saving replaced the image with its own markdown source. No error, no refusal, and the write reported success. The body editor now writes a picked path as a URL, and a destination that still needs it is wrapped the way CommonMark writes one (`![a](</a b.png>)`), so a path written by hand survives the round trip too. Paths for `image()` frontmatter fields are untouched: those are file references Astro imports through Vite, and encoding one would stop it resolving

-   **Saving one entry field re-spaced every flow array in its frontmatter.** Changing only the Title re-serialized the whole YAML block, so `categories: [Campaign, Digital]` came back as `categories: [ Campaign, Digital ]` — inert, but diff noise on lines the author never touched, and enough of it on a content collection to bury the real change. A save now copies every untouched key's original bytes back over the re-emitted ones, so spacing, quoting and block indentation survive exactly as written, whichever convention the file follows. Only the keys you actually changed are re-serialized

-   **Every `<script>` on the page was served raw and broken on Astro 7.** The self-annotation transform stamped `data-astro-source-*` onto every lowercase element, `<script>` and `<style>` included, and Astro treats a script carrying an attribute it does not recognise as `is:inline` — no bundling, no TypeScript, no import resolution, no `type="module"`. Dev pages died with `Cannot use import statement outside a module`, `/_image` returned 500s, and Astro's own `ClientRouter` broke along with the project's code. Neither tag is editable, so both are now left alone. `astro build` was never affected — the integration registers nothing for it

-   **Leaving edit mode discarded an open expression or markup draft.** The admin bar's *Save & exit* wrote an inline text edit but merely *closed* a source popup, so whatever had been typed into it went nowhere — and, since the backdrop swallows a pointer click on the bar, the keyboard was the way to reach it. A popup holding a changed draft now writes that draft on the way out, and a save the server refuses keeps the panel open with the text intact **and** edit mode open with it, so the reason can be read and the retry made

-   **A new entry wrote `false` over a boolean's schema default.** The create drawer sent every control that held a non-empty value, and an untouched checkbox holds `false` — so a `published: z.boolean().default(true)` field arrived in the new file as `published: false`, without anyone having said so. Creation now sends only the fields you actually filled in; everything else is left out of the file, which is what lets the schema's default apply. An unticked box in a new entry says **not set** and names the default it will take, rather than presenting its own idle state as a decision

-   **Creating an entry left you on the page you started from.** The create navigates to the new entry's route, waiting for Astro's content layer to sync it first — but the write that triggers that sync full-reloads the page, and the wait lived only in the reloaded document's own promise, so the destination went with it. The destination is now remembered across the reload and the wait picked back up on the next boot, with its ~10s budget measured from the create rather than from the boot. The record is consumed the moment the jump is made, so arriving cannot re-arm it, and it expires so a poll nothing ever finished cannot hijack a later visit

-   **A field's label did not name its control.** In the entry drawer and Settings alike the visible label was a sibling of the input with nothing tying the two together — no `for`, no id, no `aria-label` — so a screen reader reached an unnamed box, and clicking the label did nothing. A checkbox was worse: the only thing labelling it was its own state word, so *Published* announced itself as "On". Every control the shared field renderer builds is now named by the label above it — clicking the label focuses the field and ticks a checkbox — with the help line, the error and a checkbox's "not set" attached as its description instead

-   **The keyboard walked straight out of an open panel.** A backdrop stops the pointer and nothing else, so Tab left the popup or drawer that was up and carried on through the site's navigation, the page's links, Astro's dev toolbar and the admin bar — with the modal still on screen and no way back to it but Shift+Tab. Every panel and drawer now says it is a dialog, names itself by its title, and holds the keyboard: Tab cycles its own controls and wraps, focus that lands outside is taken back, and closing restores focus to whatever opened it. Traps stack, so the media modal opened over the entry drawer hands the drawer its own back on close, and the drawer's rich-text body — a light-DOM node slotted into the shadow tree — is part of the cycle rather than being locked out of it

-   **Clicking *Save & exit* during an inline edit saved but did not exit.** The pointer going down blurs the edit, which commits it, so by the time the button would have received its click the write was already in flight — and the button disabled itself for exactly that phase, swallowing the click that asked for the exit. The bar came back after the reload still saying *Editing*. The exit control now stays live while a write is in flight: pressing it is what started that write, and leaving already knows how to wait for one to land before it goes

-   **A date field rejected a typo with "Invalid input: expected date, received Date."** `z.coerce.date()` runs `new Date(…)` before it type-checks, so an unreadable string reaches zod as an *Invalid Date* — an object of exactly the right type — and zod described the internals rather than the mistake. A date field that cannot read its value now says **"not a date we can read"**; every other type is still explained by zod
-   ***Open page source* opened the wrong file** — typically a navigation or header component instead of the page's own template. It picked whichever source file rendered the most annotated elements on the page, and since component tags are never annotated, a markup-dense `Nav.astro` outscored a page that mostly composes components (ties went to the nav too, being first in document order). The file now comes from **Astro's own route manifest** — the route serving the URL you are on, matched the way Astro matches it, base prefix and trailing-slash style included — and the toast names the route pattern it resolved. When no route matches, it says so and opens nothing rather than guessing at a file
-   The collection designer's two-store legend was being repainted in the **host page's** body colour, dropping it to 2.7:1 on the playground. The overlay styles itself inline precisely so host CSS cannot reach it, but that only protects the element carrying the declaration: the legend's `<p>` children took their colour by *inheritance*, and an ordinary `p { color: … }` rule on the page outranks an inherited value. Every block-level element in the overlay — each `<p>` and `<label>` that was relying on inheritance — now sets its own colour, so a host stylesheet that styles elements by tag can no longer repaint overlay text
-   `src/server/unsplash-routes.ts` carried three **raw NUL bytes** in a template literal used to build a search cache key, which made the whole file read as binary: `grep` reported no matches in it and `file` called it `data`, so ordinary searches over the codebase silently skipped it. They are now `\0` escapes, which is the same value at runtime
-   A freshly uploaded or imported image showed as an empty box until the page was reloaded. Vite's static middleware 404s a file for a short window after it lands on disk, and the browser then caches that 404 for the life of the page — so the load fired the instant the write returned was the one attempt that could never succeed. Previews and thumbnails of just-written files now retry briefly, each attempt with a fresh query string; the path written into your source is unaffected
-   Opening a panel *above* another one (the media picker over the entry drawer) left the drawer owning no interaction slot once the panel closed, so its Escape and backdrop silently stopped working with unsaved fields still in it. The slot is now handed back to whoever held it rather than simply cleared
-   The label in a pill button (the popups' **open**, the hover pill's **open** and **copy**) sat about 1.5px low, so the button read as pushed down — the text more than the icon. Flex centring lines up the *boxes*, and a text box is asymmetric around its ink: on an 11px label it reserves ~11px above the baseline for ascenders and 2px below, while an all-lowercase word ("open", "copy") only paints the ~6px x-height band. The label is now lifted onto the pill's centre; the icon, whose glyph does fill its box, was already right

### Added

-   **Text rendered through an `{expression}` is editable.** `<h1>{title}</h1>` and — the case this was built for — a card in a `.map()` loop (`{benefits.map((b) => <h3>{b.title}</h3>)}`) used to be a flat refusal. Such text now classifies as `expression`: the click opens a **value popup** titled with where the string lives (`benefits[].title`), and the edit is written to that string in the frontmatter, never to the template. **Which item of a loop you clicked is identified by the text the page showed** — every card shares one source location, so the item whose value equals what you saw is the one patched, and two items reading exactly the same way refuse rather than guess. A DOM sibling index was rejected for this: a `.filter()`, `.sort()` or `.slice()` in the chain would silently mis-target, and that failure would be invisible. The same match doubles as the verify step, so a stale page writes nothing. Only plain strings in the *same file's* frontmatter are traced; computed expressions, template literals carrying `${…}`, chained calls, nested access (`{b.meta.label}`) and imported arrays keep today's refusal. No new dependency: `@astrojs/compiler` already hands over the expression text and the `.map()` head, so the frontmatter is located by scanning rather than by parsing — a real JS parser would mean shipping `typescript`, which ordinary Astro projects don't have

An element holding only plain text keeps inline editing, but can gain its first inline tag through this path. The allowed tags sit under the box as **buttons**: with text selected a tag wraps the selection and leaves it selected so tags can be stacked, otherwise it drops an empty pair at the caret — `<br>` inserts alone and `<a>` arrives as `<a href="">` with the caret inside the quotes. -   `buildImageField` now takes an options object rather than positional `(initial, onChange)` arguments, so it can receive the field's asset mode and entry path. Internal to the client overlay; no effect on the public option surface

### Security

-   New `paths.ts::resolveUploadDir` is the single gate for a client-requested upload directory: realpath-free string confinement to the configured asset directories, falling back rather than throwing. Uploads continue to write only new asset files, never source patches

## \[0.5.0\] - 2026-07-24

### Added

-   **CSS class/ID inspector in the hover pill.** With the inspector on (the new `cssInspector` option, default `true`), the hover pill grows a second row listing the element's classes and its ID as chips. Hovering a chip pops a card of the CSS rules that element actually matches through that class/ID — selector and syntax-highlighted declarations, read straight from the browser's `document.styleSheets`, so the whole display needs no server round-trip. Each rule with a resolvable source offers an `open ↗` that jumps the editor to (near) the rule. Rules from cross-origin stylesheets are skipped; Astro's `astro-*` scope class is filtered out; a rule whose source can't be resolved (inline `<style>`) still shows its CSS, just without the open link
-   New `cssInspector` option (default `true`); `false` disables the whole surface (no chips render). New `/inspect/open` endpoint backs the open-at-rule jump — it best-effort locates the selector in its source (for `.astro`, only within `<style>` blocks) and launches the editor there, falling back to the file top on a miss. The jump additionally honors `openInEditor`; the `.css` extension is admitted for *opening* only (never the write-side `editableExtensions`), and the path stays confined to `contentRoots`, so `node_modules`/external CSS is still excluded
-   New `atx-*` theming hooks for the inspector: `.atx-tooltip-row` (the pill's loc/verdict line), `.atx-tooltip-chips` and `.atx-tooltip-chip` (the class/ID chips), and the rules card `.atx-tooltip-rules` with `.atx-tooltip-rule`, `-sel`, `-decl`, `-foot`, `-src`, `-open`, and `.atx-tooltip-rules-empty`

### Fixed

-   Elements rendered by a package no longer spam the dev log with `classify failed: path is outside the editable content roots`. Astro's `astro:assets` `<Image>` renders through `node_modules/astro/components/Image.astro`, and that is the path the source annotation carries — so on any site using `<Image>`, merely *hovering* (the tooltip verdict calls `/classify` too) threw a 400 and logged a WARN. An out-of-root path is a legitimate "not editable here" answer, so `/classify` now returns a normal `dynamic` verdict for it, naming the package when the path is inside `node_modules`. Clicking the hover pill's `file:loc` label on such an element hits `/peek`, which likewise now refuses with an explanation (200 + `refused`, no source returned) instead of a 400
-   `POST /peek` responses gained an optional `refused` field carrying that explanation; the peek panel renders it in place of the code pane
-   Overlay panels now scroll on host pages that run a smooth-scroll library. Lenis, Locomotive and GSAP ScrollSmoother `preventDefault()` every `wheel` event on `window` and drive the page themselves, so a nested overflow container never scrolled — trying to scroll the source peek moved the page underneath it instead. Every scrollable surface (source peek, panel and drawer bodies, the asset list, the rich body editor) now goes through a shared `isolateScroll` helper: `overscroll-behavior: contain`, the `data-lenis-prevent` / `data-scroll-ignore` opt-out attributes those libraries resolve with `closest()`, and passive `wheel`/`touchmove` listeners that stop propagation before a window-level listener sees them. Nothing calls `preventDefault`, so page scrolling outside the overlay is unchanged

### Changed

-   The hover pill now sits fully above the highlighted element, positioned by its measured height (dropping just below only when there's no room above), so the new class/ID chips row — or any future taller pill — never overlaps the element. It previously used a fixed offset that assumed a single-line height
-   The overlay controls (`.atx-controls`) now sit `16px` from the bottom of the viewport instead of `64px`. The former offset lifted the Edit/entry pills clear of Astro's dev toolbar bar; they now sit lower and may overlap the toolbar when it's shown. The hold-to-navigate hint (`.atx-toggle-hint`) now sits to the left of the Edit pill rather than below it, so it stays on-screen at the new lower position
-   `paths.ts` now exposes `checkEditablePath()`, a non-throwing form of the path gate returning `{ok, code, reason}`, with `validateEditablePath()` re-expressed as the throwing wrapper over it. Read-only routes (`/classify`, `/peek`) use the former so they can answer instead of erroring; every route that writes or launches a file (`/apply`, `/open`, and the entry routes) keeps the identical throwing gate. Package internals stay unwritable — widening `contentRoots` to include `node_modules` remains the wrong fix and is called out as such in the README

## \[0.4.0\] - 2026-07-20

### Added

-   **Astro 7 support via self-annotation.** Astro 7's Rust compiler doesn't emit the `data-astro-source-*` attributes the feature rides on, so the integration now injects them itself: a pre-compiler Vite transform (`src/server/annotate.ts`) parses each `.astro` file with the WASM compiler and stamps every plain element with the same file/loc annotation Astro 5/6 emitted — loc-rule-identical to the patcher, so classify/apply work unchanged against the on-disk source. Verified end-to-end on Astro 7.1.1 (annotation coverage, classify, inline edit, on-disk write, post-HMR re-capture). Upstream: [withastro/compiler-rs#96](https://github.com/withastro/compiler-rs/issues/96)
-   New `sourceAnnotations` option (`'auto'` | `'force'` | `'off'`, default `'auto'`): `'auto'` injects only on Astro ≥7 (or when the Astro version can't be resolved); `'force'` always injects — which also lifts the dev-toolbar requirement on Astro 5/6; `'off'` never injects. The peer range widened back from `>=5.0.0 <7` to `>=5.0.0 <8`
-   New `entryEditor.collections.<name>.extension` option (`'.md'` | `'.mdx'`) fixing the extension used for entries created via the panel

### Fixed

-   Image edits that change both the file and the alt text are now written in a single atomic pass, closing a partial-failure window. The image panel previously sent two sequential `/apply` requests (src, then alt); if the first succeeded and the second failed, the file was left half-updated while the overlay reverted both attributes, so page and source disagreed until reload. `/apply` now takes an `ops` array and the server does one verify-all-then-write-once pass — a single failing op writes nothing to disk
-   Entry create now matches the collection's file extension instead of always writing `.md`: the per-collection `extension` config wins; otherwise, when every existing entry in the collection shares one extension, new entries follow it (an all-`.mdx` collection gets `.mdx`); mixed or empty collections still fall back to `.md`. The chosen extension is validated against `editableExtensions` (422 when excluded)
-   `decodeEntities` now knows the common typographic named entities (`&mdash;`, `&ndash;`, `&hellip;`, curly single/double quotes, `&laquo;`/`&raquo;`, `&middot;`, `&bull;`, `&copy;`, `&reg;`, `&trade;`, `&sect;`, `&deg;`, `&times;`, `&euro;`, `&pound;`), so editing text whose source spells them as references no longer refuses with a `mismatch`. Unknown entities still pass through undecoded and fail safe
-   After creating an entry the client now polls the new page's URL until Astro's content layer has synced it (250ms interval, ~10s cap, then navigates regardless) instead of a fixed 800ms wait — a slow sync lands on the rendered page instead of a 404

### Changed

-   Narrowed the `astro` peer range to `>=5.0.0 <7` (superseded above by self-annotation, which widened it to `<8`). Astro 7 makes the rewritten Rust compiler (`@astrojs/compiler-rs`) the default, and it no longer emits the `data-astro-source-file` / `-loc` attributes the whole feature depends on — so click-to-edit was inert on Astro 7 (the entry drawer, which uses the page-source meta + content config, still worked). Filed [withastro/compiler-rs#96](https://github.com/withastro/compiler-rs/issues/96) upstream
-   The playground now pins `astro` to `^7.0.0`, so the self-annotation regime is what the manual checklist exercises (Astro 5/6 keep their coverage through the loc-parity tests in `tests/annotate.test.ts`, which pin the same rules their compiler uses)
-   The image swap panel and the entry drawer's image field now share one `buildAssetPicker` primitive (`src/client/editors/asset-picker.ts`) for the upload drop-zone and existing-asset browser, instead of each carrying its own copy. As a side effect the entry drawer's image picker gains the swap panel's richer list — retry-on-load-failure, a neutral fallback tile for thumbnails that don't load, hover states, and a highlight on the current selection
